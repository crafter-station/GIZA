# Agent Guide

Giza is an educational 3D web experience about the pyramids of Giza. The master plan, with every decision and the phase checklist, is [plan.md](plan.md) (written in Spanish). Read the current phase there before starting work.

## Conventions

- **Language**: everything is in English: code, identifiers, docs, commit messages, and UI copy. The only Spanish file is `plan.md`. Spanish exists only as a secondary UI locale.
- **No comments in code**: source files (`.ts`, `.svelte`, `.css`, `.html`, configs) contain no comments, including JSDoc. Express intent through names, types, and small functions; explanations belong in `plan.md` or the READMEs.
- **Stack**: SvelteKit 3 + Svelte 5 (runes) with `adapter-static`; three.js `WebGPURenderer` + TSL only (no `ShaderMaterial`, no `onBeforeCompile`); pnpm with exact versions (`save-exact`). Do not upgrade `three` in the middle of a phase.
- **Imports**: use the `#lib/...` alias (`$lib` does not exist in this SvelteKit version) and explicit `.ts` extensions, so the same modules run in Vite and in Node tools (`node tools/*.ts`).
- **Engine vs UI**: the engine in `src/lib/` is framework-free TypeScript; Svelte components talk to it through a typed store and never touch three.js objects.
- **UI components**: build interactive components with [Bits UI](https://bits-ui.com) primitives (`Button`, `Select`, `Toggle`, `Slider`, `Dialog`, `Tooltip`, `Progress`…) styled with Tailwind; do not hand-roll widgets that Bits UI provides.
- **Visual identity**: use the design tokens in `src/routes/layout.css` (`papyrus`, `ink`, `lapis`, `gold`, `ochre`, `faience` colors; `font-display`, `font-glyph`; `papyrus`, `frieze`, `beads`, `register`, `glyph` utilities) and the components in `src/lib/ui/egypt/`. Hieroglyphs are real Unicode signs from `src/lib/content/hieroglyphs.ts`, verified by code point; never invent or AI-generate them.
- **Facts**: every figure shown to users comes from `src/lib/data/*.ts` as a `Fact` with sources (`src/lib/content/sources.ts`). Hypotheses are labeled as such.
- **Assets**: heavy sources go to `assets-src/` (Git LFS); built runtime files go to `static/`. Third-party assets (models, data) need a README with author and license; images generated by the project owner do not. The owner converts images to WebP/AVIF; agents do not run image conversion. Never copy code or assets from `seijaku/` or `open-water/` (study only).

## Commands

| Command | Purpose |
| --- | --- |
| `pnpm dev` | Development server |
| `pnpm check` | Svelte and TypeScript type-check |
| `pnpm lint` / `pnpm format` | Biome check / fix |
| `pnpm test` | Vitest unit tests (Node) and component tests (browser) |
| `pnpm test:e2e` | Playwright end-to-end tests against the production build (Chromium, Firefox, WebKit, mobile) |
| `pnpm build:terrain <tile.tif>` | Rebuild the Giza heightmap from the Copernicus DEM tile |
| `pnpm build:stars` | Rebuild the 2560 BCE star positions from the Bright Star Catalogue |

## Browser QA for Agents

Use `agent-browser` (installed as a dev dependency) to look at the running app: snapshots with element refs, screenshots, and console errors with few tokens. Start `pnpm dev`, then:

```sh
pnpm exec agent-browser open http://localhost:5173 --webgpu
pnpm exec agent-browser snapshot -i
pnpm exec agent-browser screenshot shot.png
pnpm exec agent-browser console
pnpm exec agent-browser errors
```

Write repeatable checks as Playwright tests in `tests/e2e/`; use agent-browser for exploration and visual review, not as the test suite.
